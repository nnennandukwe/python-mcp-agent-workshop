# Plan: Integration Test for Example Client (Issue #39)

## Context

`examples/mcp_client_example.py` exists but isn't covered by any test. It can silently break as the codebase evolves. The goal is to add an integration test that runs the example client end-to-end and verifies it works.

## Approach

Create **one new file**: `tests/test_example_client.py` with 2 test methods.

The example client already handles server lifecycle internally — each of its 5 examples spawns a fresh `python -m workshop_mcp.server` subprocess via stdio. So our test simply runs the client script and checks the output.

### Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| How to invoke the client | `sys.executable` (not `poetry run`) | Already in the virtualenv when pytest runs; matches what the client itself does for the server |
| Timeout | 60s (not 30s as issue suggests) | Client has its own 30s per-request timeout internally; 60s avoids racing with it on slow CI |
| Working directory | `cwd=PROJECT_ROOT` resolved from `Path(__file__)` | Works regardless of where pytest is invoked |
| Number of tests | 2 methods | One for basic pass/fail, one for verifying all 5 example sections appear |

- Runs `sys.executable examples/mcp_client_example.py` via `subprocess.run`
- Asserts return code == 0
- Asserts "All examples completed!" in stdout
- Includes stdout/stderr in failure messages for diagnostics

### Test 2: `test_client_output_contains_all_example_sections`
- Same invocation
- Asserts all 5 example section headers appear in stdout ("Example 1: Initialize" through "Example 5: Error Handling")
- Uses `pytest.skip` if the script itself failed (avoids confusing double-failure)

**Issue**: The claim that "60s gives comfortable headroom" is mathematically misleading. This is not merely a pedantic concern. If, for example, the server is running on a slow CI node and three of the five subprocesses take 15 seconds each (still within their individual 30-second budgets), the test would fail with a `subprocess.TimeoutExpired` error after 60 seconds even though nothing is actually broken. **Suggestion**: Either:
